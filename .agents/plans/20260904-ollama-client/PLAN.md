# Native Ollama client, with thinking support

Adds a native Ollama model type to blorb: a new `internal/llm/ollama` package implementing `llm.Client` and `llm.StreamingClient` against Ollama's native `/api/chat` endpoint (single JSON object when not streaming, NDJSON lines when streaming), inspired by the client in ../oaillama (`internal/ollama` there). A new `"type": "ollama"` model entry in blorb.json selects it; agents, engine, chat, run, and subagents work unchanged because everything consumes the provider-neutral `llm` interfaces. Wire logging (KindLLMRequest/KindLLMResponse) is included, mirroring the openai client.

Thinking is supported end to end: a new optional `reasoning_effort` field on model entries sends OpenAI's `reasoning_effort` on the openai-compatible path, and Ollama's `think` field on the ollama path. The accepted values are the union of both scales: `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` — empty means the server default. Both paths pass values through verbatim (which values a given model accepts is the server's business); the one exception is `none`, which the ollama client maps to `think: false` because Ollama rejects the string `none`. Decoding is unchanged on both paths: server-extracted thinking already maps to `llm.Message.Reasoning` (openai's `reasoning_content`, Ollama's `message.thinking`). Tool call ids are synthesized when Ollama omits them, as ../oaillama does, so the engine's history and repair logic keep working.

## Commit 2: Ollama wire types and translation

> Create the package `internal/llm/ollama` with `types.go` holding the Ollama wire shapes and `translate.go` converting between them and the neutral `llm` types. No network code yet; everything in this commit is pure and unit tested.
>
> Wire types (JSON tags matching Ollama's `/api/chat` API, as mirrored in ../oaillama `internal/ollama/types.go`):
>
> - `chatRequest`: `model`, `messages []wireMessage`, `stream bool` (`json:"stream,omitempty"`), `think any` (`json:"think,omitempty"` — false, or a level string passed through from `reasoning_effort`), `tools []wireTool` (`json:"tools,omitempty"`). No `options`, `format`, `logprobs`, or `tool_choice`: blorb's neutral `llm.Request` carries none of them. Note `think` is `any` rather than `bool`: it carries either the boolean or the level string, and `omitempty` on an interface holding `false` still serializes it (interfaces are empty only when nil), so `think: false` reaches the wire.
> - `wireMessage`: `role string`, `content string` (no omitempty; Ollama accepts `""`), `thinking string` (`json:"thinking,omitempty"`, decode-only), `tool_call_id string` (`json:"tool_call_id,omitempty"`), `tool_calls []wireToolCall` (`json:"tool_calls,omitempty"`).
> - `wireToolCall`: `id` (`json:"id,omitempty"`), `function wireFunction` where `wireFunction` is `name string` plus `arguments json.RawMessage` — Ollama sends arguments as an embedded JSON object, not a string.
> - `wireTool`: `type string` plus `function wireFunctionDefinition{name, description string; parameters json.RawMessage}` — Ollama uses the OpenAI function envelope for tool definitions.
> - `chatResponse`: `model`, `created_at string`, `message wireMessage`, `done bool`, `done_reason string`, `prompt_eval_count int`, `eval_count int`.
>
> Translation, in `translate.go`:
>
> - `wireRequest(req llm.Request, defaultModel, reasoningEffort string) chatRequest`: model is `req.Model` or `defaultModel` when empty (mirror openai's `firstNonEmpty`); each neutral message becomes a wire message (role, content, tool_call_id); an assistant message's neutral tool calls become wire tool calls with `arguments` parsed from `tc.FunctionArgs` via `json.Unmarshal` into `json.RawMessage` (empty string becomes `{}`), returning a wrapped error when the arguments are not valid JSON. Thinking is deliberately NOT sent back to the server (matching ../oaillama, which drops it in translation): a final answer's reasoning is stale by the next request. Each `llm.Tool` becomes `wireTool{Type: llm.ToolCallType, Function: ...}` carrying the name, description, and parameters verbatim. `think` maps from the model's reasoning effort: empty effort omits the field (server default), `none` sets `think` to `false` (Ollama rejects the string `none`, so the boolean form is the only way to disable thinking), and every other value passes through verbatim as the level string — `minimal`/`xhigh` included, since which levels a given model accepts is the server's business.
> - `neutralResponse(chunk *chatResponse) *llm.Response`: role assistant; `Content` and `Thinking` from the message (thinking maps to `Reasoning`); each wire tool call becomes a neutral `llm.ToolCall` with `FunctionArgs` as `string(arguments)` (empty becomes `"{}"`); `Type` defaults to `llm.ToolCallType` when absent; `ID` is the wire id, or `call_` + 16 hex chars from `crypto/rand` (a small `randomHex` helper, as in ../oaillama) when Ollama omitted it — Ollama does not send tool call ids, and the engine needs non-empty ids for history matching and repair. `FinishReason` maps `done_reason`: `length` to `llm.FinishLength`, `tool_calls` to `llm.FinishToolCalls`, everything else to `llm.FinishStop` (mirroring ../oaillama's `mapFinishReason`). `Usage` is built from `prompt_eval_count` and `eval_count`, total their sum. `ID` stays empty (Ollama has no response id; nothing consumes it).
> - A neutral tool call whose function name is empty is not filtered here; that validation belongs to the client, like openai's `hasToolCallWithoutName`.
>
> Tests in `internal/llm/ollama/translate_test.go`: table tests for `wireRequest` covering messages (roles, content, tool_call_id), tool call history conversion including empty arguments becoming `{}` and invalid arguments erroring, tool definitions producing the `{"type":"function","function":{...}}` envelope with the exact JSON keys, and the think mapping (absent effort omits the field; `none` serializes `"think":false`; every other value serializes verbatim as the level string, e.g. `"think":"minimal"`); table tests for `neutralResponse` covering done_reason mapping (stop/length/tool_calls and unknown values), usage mapping, thinking to reasoning, arguments object to string, and id synthesis (assert non-empty with `call_` prefix; do not assert the random value). No other packages change.

## Commit 3: Ollama client: non-streaming Chat with wire logging

> In `internal/llm/ollama/client.go`, add `Config` and `Client` implementing `llm.Client`, mirroring the structure and limits of `internal/llm/openai` (reuse its constant values and helper patterns; copy the small helpers rather than exporting them from openai):
>
> - `Config`: `BaseURL` (server root, e.g. `http://localhost:11434`; `/api/chat` is appended), `Model` (default model when a request does not carry one), `ReasoningEffort` (passed through to `wireRequest` as the `think` mapping, Commit 2), `APIKey` (sent as `Authorization: Bearer ...` when non-empty — Ollama cloud needs it, local Ollama ignores it), optional `HTTPClient *http.Client` (default: shared client with a 5 minute timeout, via `sync.Once`, so a hung server cannot block a turn), and `Sink logging.Sink` (optional wire logging; nil disables).
> - `New(cfg Config) (*Client, error)`: validates the base URL exactly as openai does (parse, http/https scheme, non-empty host).
> - `Chat(ctx context.Context, req llm.Request) (*llm.Response, error)`: build the wire request via `wireRequest` (passing `c.cfg.ReasoningEffort`), POST it to `BaseURL + "/api/chat"` with `Content-Type: application/json` and the bearer token when set, honouring ctx. Write a `logging.Record{Kind: KindLLMRequest}` with the endpoint URL, cloned request headers, and a copy of the marshalled body before sending (best-effort; write errors ignored), exactly like openai's `post`. On a non-2xx status, read the body with `io.LimitReader` up to the shared `maxBodyLen` (16 MiB), log it as a `KindLLMResponse` record with the response headers plus synthetic Status key (openai's `responseHeaders`/`cloneHeader` pattern), and return `fmt.Errorf("ollama chat: unexpected status %d: %s", ...)` with the UTF-8-safe truncated body (openai's `truncate`). On 2xx, read the whole body with the same limit (erroring when the limit is hit, as openai does), log it as the `KindLLMResponse` record, then decode ONE JSON value with `json.Decoder` (this accepts both a bare object and a single NDJSON line), and build the neutral response via `neutralResponse`. Reject a decoded response whose `done` is false (the server did not finish) and one carrying a tool call with an empty function name (openai's `hasToolCallWithoutName` pattern), both as decode errors with the truncated body included.
>
> Tests in `internal/llm/ollama/client_test.go` using `httptest.NewServer`, mirroring the openai client's test style: the request reaches `POST /api/chat` with the right JSON body (model defaulting from Config, messages, tools, and the `think` field when `ReasoningEffort` is set) and `Content-Type`; the bearer header is present when the key is set and absent when not; a 2xx single-object response (content, thinking, done, done_reason, counts) yields the expected neutral response including synthesized tool call ids and usage; a 404 with an `{"error":...}` body yields an error carrying the status and body snippet; `New` rejects bad base URLs (bad scheme, missing host); a sink records one request and one response body with the endpoint URL (assert the record fields; best-effort ignores write errors). No other packages change.

## Commit 4: Ollama streaming: ChatStream over NDJSON

> In `internal/llm/ollama/client.go` (streaming parts) add `ChatStream`, so `Client` satisfies `llm.StreamingClient` (`var _ llm.StreamingClient = (*Client)(nil)` compile check). Ollama streams NDJSON: one `chatResponse` object per line, terminating with a `done: true` line carrying `done_reason` and the token counts.
>
> - `ChatStream(ctx, req, onDelta)`: build the wire request with `Stream: true` (and the same `think` mapping), POST it via the same path as `Chat` (share the request-building helper so the two paths cannot drift), with the same non-2xx handling, error body limits, and error-path response logging. Then read the body line by line with `bufio.Scanner` (buffer sized like openai's stream reader, capped at `maxBodyLen`): skip empty lines; unmarshal each line into `chatResponse`, skipping lines that fail to parse (tolerant of keepalives, like openai skipping non-JSON SSE payloads); for each chunk emit deltas via `onDelta` and accumulate, mirroring openai's `streamAccumulator` shape:
>   - a non-empty `message.content` fragment emits `llm.Delta{Content: ...}` and appends to a `strings.Builder`; `message.thinking` likewise emits `llm.Delta{Reasoning: ...}` — in chunk order, so reasoning and text interleave as they arrive;
>   - each tool call in a chunk emits `llm.Delta{ToolCall: &llm.ToolCallDelta{...}}` with `Index` set to the call's position within the chunk's `tool_calls` array (matching ../oaillama's `StreamTranslator`, which keys streamed calls by chunk position; Ollama delivers a message's tool calls within a single chunk), plus `ID`, `Type` (default `llm.ToolCallType`), `Name`, and `Arguments` as the string form of the arguments fragment. Accumulate by index into a map with an order slice (openai's pattern): first fragment for an index establishes id/name, later fragments at the same index concatenate arguments;
>   - the `done` chunk captures `done_reason` and usage (`prompt_eval_count`/`eval_count`) and ends the stream;
>   - cap accumulated content, reasoning, and per-tool-call arguments at the openai `maxContentLen` equivalent, erroring with the same "exceeds %d byte limit" phrasing when exceeded, so a runaway stream cannot exhaust memory.
> - An `onDelta` error aborts the stream and is returned. A stream that ends at EOF without a `done` chunk still returns the accumulated response (empty finish reason and zero usage), mirroring openai's tolerance for a `[DONE]`-less stream; a stream that carried no parseable chunk at all errors with a "no data in stream" decode error, so an empty stream cannot surface as a silent empty answer. Before returning, synthesize ids for accumulated tool calls missing them (the `call_` hex form from Commit 2) and reject tool calls with empty names, as in `Chat`. Honour context cancellation (the transport surfaces it as a body read error; return it wrapped like openai's `readStream` does).
> - Wire logging, mirroring openai's `readStream`: on the happy path, log one `KindLLMResponse` record whose body is the assembled response marshalled back into a synthetic final `chatResponse` (`done: true`, assembled message, done_reason, counts), so streaming and non-streaming logs carry directly comparable bodies; on error after data arrived, log the partial assembly; with no data at all, log an `error: ...` body. Best-effort; write errors ignored.
>
> Tests in `internal/llm/ollama/client_test.go`: a server streaming content fragments then a done chunk yields deltas in order, a final response whose content is their concatenation, the done chunk's finish reason and usage; thinking fragments surface as reasoning deltas and accumulate into `Message.Reasoning`; a tool call stream (id-less, arguments as an object) yields tool call deltas in order and a final message with one complete tool call with a synthesized id and string arguments; two tool calls in one chunk get indexes 0 and 1; the request body includes `"stream":true` and the `think` field when `ReasoningEffort` is set; a non-2xx status surfaces status and body; a stream that ends without `done` returns the accumulated response; an empty (or all-malformed) stream returns the "no data" error; context cancellation mid-stream returns an error; oversized content or argument accumulation returns the limit error; a sink receives the request record and the assembled response record. No other packages change.
